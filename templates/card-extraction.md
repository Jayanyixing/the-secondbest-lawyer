# 从判决书抽卡：口径与顺序

一张卡 = **一个争点**。不要一份判决只抽一张，也不要一个判决抽十张碎卡。

## 抽取顺序（固定五步）

1. **定争点**：优先用法院自己归纳的“争议焦点”；没有归纳的，从“本院认为”段落里找它实际裁判的问题。
2. **抓原文**：在该争点的说理中，逐字抄一句 8–60 字的关键句——可以是法院的结论句，也可以是它采信/否定某证据的那句。**不许改写、不许拼接**。
3. **写要点**：用自己的话把法院的处理抽象成一句规则，**不得超出说理范围**（判决没说 A，就不能写 A）。
4. **写胜负手**：这个案子是什么决定了结果？证据、程序、时间点、还是某个抗辩没提。这一栏最难写，也最值钱；写不出就留空，不要凑。
5. **标出处**：文件名 + 页码／段落，或案号 + 判决书第几段。

## 字段对应

| 字段 | 从哪来 | 不许写什么 |
|---|---|---|
| `case_no` | 判决书首部，**脱敏**（保留 X）；规则卡填《法规名》或会议纪要名称 | 完整真实案号 |
| `cause` | 案由 | 自拟案由 |
| `issues` | 争议焦点 | 当事人主张 |
| `holding` | 法院对该争点的处理 | 代理意见 |
| `our_side` | **本卡适用于哪一方**——我用这张卡时站在什么位置（原告／被告／劳动者／用人单位／承包人／发包人） | 原审诉讼地位（这是两回事，不要混） |
| `key_point` | 胜负手（可空） | 泛泛的“证据不足” |
| `quote` | 说理段落原文 8–60 字 | 概述、拼接、判决主文以外的内容 |
| `source` | 文件名 + 页码／段落 | “某判决” |
| `tags` | 3–5 个检索词 | 无信息量的标签 |

## 判例卡与规则卡

`kind: judgment`——有裁判文书的案例，`case_no` 为案号或典型案例编号。

`kind: rule`——没有案号但有规则含量的文本：法官会议纪要、司法解释条文、审判指导意见。这一类**不能当判例引用**，检索时应与判例卡分开看。

规则卡的 `quote` 要取**这份文件自己的主张**（例如纪要的“采甲说”结论），不要取它在论证中援引的条文。确实只能取被援引条文时，在 `source` 注明「援引条文」，`holding` 写「纪要援引……」，不能写成纪要自己的观点。

规则卡摘录上限放宽到 120 字（判例卡仍是 60），因为纪要的结论句往往一长句才完整。

## 常见错法

- 把**当事人主张**写成“法院认为”；
- 只抽一审结论，没标后续二审改判；
- 同一争点抽了两张，案号不同但其实是关联案；
- 摘录写成了概述（“法院认为买方应付款”——这是转述，不是原文）；
- 要点里塞进自己的策略建议——那是 `key_point` 该干的事。

## 入库前

```bash
python3 tools/lawdb.py card-add --file cards.json
```

校验不过整批不入库：九字段必填、摘录 8–60 字、案号须“（年份）…号”且带 X 遮罩、同案号+同争点不重复。
