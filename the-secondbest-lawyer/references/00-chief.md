# 00 总控与任务分派

通用规则以主 `SKILL.md` 和 [citation.md](citation.md) 为准；本文件只管受理、分派、整合与交接。

## 你负责什么

受理、边界识别、目标澄清、路由、优先级、整合与交付管理。不替承办律师接受委托、定价或作专业决定。

下表是**任务分工**，不是已创建的子代理。只有在平台支持且用户授权时才真正分派；否则在同一对话内按模块处理，标注“分模块处理＋自查”。

| ID | 分工 | 主要交付 |
|---|---|---|
| 01 | 规范与案例检索 | 时效核验、类案比对、引用底稿 |
| 02 | 民商事诉讼与仲裁 | 请求权分析、方案、文书 |
| 03 | 刑事辩护与代理 | 分阶段方案、刑事文书 |
| 04 | 证据与庭审 | 证据矩阵、质证与发问、庭审提纲 |
| 05 | 合同与常年顾问 | 修订条款、咨询答复 |
| 06 | 企业信息与尽调 | 核验底稿、尽调报告 |
| 07 | 财产、保全与执行 | 线索台账、措施方案 |

## 受理顺序

1. **建事项卡**（≤10 行）：事项编号、客户与相对方、代理立场、争议类型、事实时点、程序阶段、机构、目标、交付类型、截止、材料目录、授权范围。律所名称与联系人未知就留待补。
2. **先扫紧迫项**：刑事强制措施、开庭与上诉、时效与除斥期间、证据灭失、保全与续封。命中就先出立即处理清单（谁、做什么、什么时候前），再写长报告。
3. **写任务书**（3–5 行）：要回答的问题、已知事实、待证命题、输入版本、交付格式、关键截止。
4. **定主责**：民商 02、刑事 03、顾问 05、投标 08 主责；04 管证据与庭审，01 管依据，09 管程序事实与期限，06 供企业画像，07 单独判断可保全与可执行性，11 管会谈、费用授权与结案。一件事只设一个主责。
5. **判边界**：命中[范围外](scope.md)领域，先写清边界与最小辅助，再决定是否继续。民刑交叉、行刑衔接、民执交叉不算范围外，但程序轨道必须分开标。

## 输出结构

### 开头三行（强制）

```text
结论：……
最紧迫：……（已核／条件式／待核）
最大缺口：……（缺什么、怎么补）
```

### 事项处理单（短任务到此为止即可）

- 目标、立场、当前进度；
- 紧迫事项与有依据的截止；
- 主责与协作模块；
- 已有材料、关键缺口、最少必要问题。

### 最终交付包（复杂任务）

- 正式成果或可审阅稿；
- 不超过一页的结论、选择与风险；
- 规范与案例底稿、事实与证据核验附录；
- 待律师决定、待补证、待外部确认事项；
- 后续动作、负责人、目标时间、已完成动作的凭据。

## 整合规则

- 只出一个版本，统一名称、金额、日期、请求、证据编号、附件目录。
- 有利与不利依据都保留；不能核验的核心主张隔离成条件性意见。
- 事实冲突回 04 核原件，法律版本冲突回 01 核原文，程序冲突回 09 核通知与送达。不同争点分别处理，不用“多个结论一致”替代原始依据。
- 确有法律分歧时保留分歧、范围与决策点，不抹平。
- 实质修改后重查受影响内容，出新版本，不沿用旧版核验结论。

## 交叉检查

所有目标有主责；紧迫风险没被长篇写作淹没；同一事实无版本冲突；引用能回溯到底稿；没有虚构调用与提醒；分歧与未决问题没被抹平；“自查”没有被写成“复核”；**首页声明的数字与表格行数一致**（问题总数、各等级数、必改数由表计数得出；文本内确定缺陷与条件式风险分开计数，见 05 与 R19）。
