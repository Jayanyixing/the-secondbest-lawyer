# 01 法律法规与案例检索

通用规则见主 `SKILL.md`；引用登记、状态词表与降级路径必须按 [citation.md](citation.md) 执行。

## 输入

争议类型、关键事实与行为时点、代理立场、审理地域与法院层级、程序阶段、具体问题、检索截止日。缺关键事实就给分支检索，不先锁死案由。

## 检索拆解

先把问题拆成四层，各层分别检索，不混成一个关键词：

1. **实体要件**：请求权基础或罪名构成，逐要件列“要证明的命题”。
2. **举证与抗辩**：证明责任分配、抗辩与再抗辩、举证妨碍。
3. **程序**：主管与管辖、前置程序、诉讼时效与除斥期间、程序类型。
4. **救济**：请求形态、救济路径、执行可行性。

同时列**反向命题**（对方会怎么论证），支持与不利都检索。

## 规范检索顺序

0. **先查本地法条库**：`python3 tools/lawdb.py query "关键词"` 或 `article <法名> <条号>`。命中即以库内原文引用（带导入日期与哈希），并核对库的导入日期是否覆盖行为时点；未命中再走下面的联网顺序。三层数据供给见 [data-supply.md](data-supply.md)。
1. 法律全文 → 制定机关官方页面（国家法律法规数据库 `flk.npc.gov.cn`）。
2. 司法解释、批复、会议纪要 → 最高人民法院、最高人民检察院官方发布。
3. 行政法规、部门规章、地方性法规与规范性文件 → 相应制定机关；北京文件查北京人大数据库与发布机关，区分地方性法规／政府规章／规范性文件／法院文件。
4. 修订与废止 → 修改决定、废止决定、过渡条款、施行日期。

建**版本时间线**：行为发生 → 行为持续 → 规范公布 → 施行 → 修订 → 废止 → 程序节点。实体与程序分别判断；刑事法律变更按从旧兼从轻等对应规则核验；不写“以最新规定为准”了事。

## 类案检索

- 检索式由「案由 + 要件事实 + 裁判理由关键词 + 地域 + 法院层级 + 年份 + 审级」组合，至少两组同义表述。
- 先找目标法院与北京相近案件，再扩展到最高法院与全国；同时找不利案例。
- 逐案核对案号、法院、日期、审级、后续裁判与生效状态；官方摘要与完整文书分开记。
- 案例类别必须区分：指导性案例（带指导案例编号）／入库参考案例（带入库编号）／典型案例／公报案例／普通裁判／仲裁裁决。案号与入库编号分列，不混为一个号。
- 转载、汇编、公众号解读不算独立案例；同一文书的不同转载只算一个。
- 不以命中数量、检索总量推断胜诉率或裁判倾向。

## 检索留痕

每次记录：平台、检索式、筛选条件、检索日期、命中量、实际打开并读到的文书、排除理由、受限原因。受限时先排除“入口临时拦截”，换官方子页、换检索引擎、换入口再判；仍不可得才标受限。

## 停止编造

- 只有标题或摘要：列为待取正文，不写裁判理由、不写“法院认为”。
- 检索为零：写“本次条件下未检索到”，不推“不存在此类判决／不存在该债务／无诉讼”。
- 官网打不开：给检索式与获取路径，候选与已核分开，不用经验补案号和条号。
- 用户提供的文书：按其实读页段引用，注明“用户提供”，不冒称已在官方库核对。
