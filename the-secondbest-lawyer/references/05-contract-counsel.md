# 05 合同与常年法律顾问

通用规则见主 `SKILL.md`；引用按 [citation.md](citation.md)。重大争议转 02，刑事线索转 03，尽调转 06，财产措施转 07。

## 输入

服务企业与**代理立场**（甲方／乙方／供应商／采购方／借款人／贷款人）、交易目标、合同类型、对手身份、签约或履行阶段、合同版本与附件、议价空间、必须保留条款、内部审批与授权。日常咨询先明确：谁、何事、何时、何地、想达到什么。

## 合同审核

1. **清点文件**：正文、附件、报价单、订单、技术或服务标准、补充协议、被引用的外部规则，列版本。附件缺失时说明哪些条款无法评价。保留原版，未经要求不覆盖用户文件。
2. **画交易闭环**：谁向谁交付什么 → 何时验收 → 何时付款 → 失败时如何补救、退出、留证。标出闭环里的每个断点，断点就是风险点。
3. **逐块审查**：主体与代理权限、标的与规格、价税与发票、交付与验收、付款条件与保障、质量与售后、违约与责任限制、解除与终止、保密、个人信息与数据、知识产权归属与许可、不可抗力与情势变更、通知送达、争议解决与管辖、合同文件优先顺序、签署与生效条件。专项条款（劳动、担保、数据、许可）按对应现行规则核，不套同一模板。
4. **分级**：高风险＝可能显著影响效力、主要权利、监管责任或退出成本；中风险＝可能引发较大履约争议；低风险＝表述与管理改进。**商业不利但合法**的条款标为商业决策，不写成违法或无效。
5. **给可替换文本**：每条含原条款位置与原文、风险触发场景、受影响方、法律依据或商业理由、首选修改、可接受备选、联动条款。不写“建议完善”“建议明确”这类空话。
6. **修订稿**：区分标注修改版与清洁版，核对定义、编号、交叉引用、金额、日期、附件、前后责任一致。只有真的编辑并核对过文件才说“已完成修订稿”；只给文字建议就说明只是建议。

## 高频风险点自检

| 风险 | 检查动作 |
|---|---|
| 格式条款 | 是否履行提示说明义务、有无排除对方主要权利 |
| 违约金 | 计算基数与比例、与实际损失偏离、调整空间 |
| 付款条件 | 是否与验收、发票、结算单绑定，条件是否可控 |
| 解除权 | 约定解除条件是否明确、通知方式是否可举证 |
| 责任限制 | 是否限制人身损害、故意重大过失，是否对己方有效 |
| 送达条款 | 地址、邮箱、微信是否约定为有效送达并约定视为送达 |
| 争议解决 | 诉讼与仲裁是否并存、仲裁机构是否唯一明确、管辖是否有效 |
| 附件与优先顺序 | 冲突时以谁为准，是否写明 |

## 日常咨询

先给结论与当日可做动作，再讲前提、依据、风险、最少补充问题。常见事项：合同履行与催收、劳动用工、公司治理与决议、印章与授权、广告与经营合规、租赁与装修。疑似刑事风险不做罪名定性。

**执业合规提示（顺带提醒，不说教）**：涉及收费与风险代理时，提示刑事、行政、群体性等案件不得风险代理，收费方式与比例按现行律师服务收费规则与所内制度核；涉及对外宣传、媒体与自媒体披露案件时，提示不得披露委托人信息与案件细节、不得作胜诉承诺；涉及双方或关联方委托时，先走利益冲突筛查。

## 输出长度

简单咨询 ≤15 行，不用表格。合同审改必给风险与修订表，结论一页。重大交易才出完整备忘。

## 标准交付

### 计数口径

首页的问题总数、各等级数、必改数一律由下表计数得出，不手填、不按印象调整：

- 风险与修订表每一行＝1 项问题；等级取「等级与触发场景」列开头的 高／中／低。
- 必改清单放在小节标题含「必改项」的位置，每行首列写「必改 1」「必改 2」……；必改数＝这些行的行数。
- 首页用散文写清三组数字（如「共 13 项问题，其中 5 项属高风险……必改 6 项」），与表不一致时以表为准，重新计数后再写。

`tools/citation_lint.py` 的 R19 核对这三组数字：自查模式下不一致报错，其他模式警告；首页数字解析不到时只提示，不猜。

### 替换条款的编号

- 替换条款要么给**整条或整组替换**，要么同时给**「修订后条款目录＋编号映射表」**（表头：原编号｜新编号｜说明；新增条款在说明里写明「原合同无此条」）。
- 一条风险牵动三个以上互相引用的条款时，默认出**完整修订稿**，不要让律师自己拼单条；需要 .docx 时用 `tools/docgen.py`，现有模板不含修订稿的，先给文字修订稿并说明未生成 Word，不写「已出 Word」。
- 单条粘贴不得断引用：替换文本里出现的「第 x.y 条」必须能在原条款、映射表或新增条款清单里找到；找不到就补映射表，或改成整条替换。

### 法律结论的出处

- 「无效」「不发生效力」「可撤销」「可调减」「按某期限处理」这类结论，必须挂对应的 N-／C- 编号；没有登记依据的，写成「法律判断待核（未登记依据）」，不写成确定结论。
- 「约定不明」分两种写：文本自身能确定的缺陷直接说；存在争议的写明争议点与两种可能，不下确定结论。
- `tools/citation_lint.py` 的 R21 只在风险表里做启发式提示（按分句判断，「」内引来的原文不算），不阻断交付，最终仍由承办律师判断。

### 必查依据清单（按交易类型）

**只查类别，不预设结论**：下列类别须现场检索、核现行效力、建底稿后再写结论。具体规范名称与条号一律现场核，本技能不写死。

| 交易类型 | 须检索的依据类别 |
|---|---|
| 股权转让 | 公司章程对转让的限制；其他股东优先购买权与通知程序；公司对外担保的决议程序与相对人审查；出资期限与未实缴出资的责任归属 |
| 担保、保证 | 公司为他人担保的决议要求；保证期间与起算；担保合同的从属性 |
| 付款与定金 | 定金的成立与交付；定金与违约金的选择适用；违约金调整 |
| 一般合同 | 格式条款的提示说明义务；解除权与通知到达；争议解决条款的独立性 |

写具体规范名称前先核其现行有效（有无修订、废止、被替代），并记入底稿；核不到就写「法律判断待核（未登记依据）」。

### 一页结论

能否建议签署及条件、必改项、可由业务决定项、签后管理动作（台账、验收、催收、留证）。签约的内部批准由企业有权人员决定。

### 咨询答复

结论 → 适用前提 → 关键依据 → 建议动作与材料 → 风险与待确认。需函件、通知、制度时给独立可用稿，内部建议不混入对外文本。

## 自检

条款可执行且符合己方立场；改动覆盖附件与引用关系；法律风险与商业偏好已分开；没编造对方已同意的价格、授权或承诺；新规没冒充现行依据。不设计虚假合同、倒签材料或违法用工方案，改给合法替代路径。
