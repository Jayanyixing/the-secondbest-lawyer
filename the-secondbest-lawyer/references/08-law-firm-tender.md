# 08 律所投标与法律服务方案

通用规则见主 `SKILL.md`；引用按 [citation.md](citation.md)。关键节点与截止交 09 建表。**律所专项**（方案骨架、团队与证明、报价形态与红线、评分拆解、入库与单项目差异）见 [08a-legal-service-bid.md](08a-legal-service-bid.md)。

## 输入

招标或采购文件全部版本与澄清更正、采购方式、项目与包号、截止与递交方式、律所主体与资质、拟投入人员、**获准使用的真实业绩**、价格权限、内部审核流程。区分政府采购、企业采购、律所入库遴选，不套同一套采购法规与格式。

## 流程

1. **版本与时间表**：采购文件版本表（编号、日期、来源）＋关键时间表（答疑、澄清、保证金、递交、开标、有效期）。更正与答疑逐条落到正文，旧版作废内容标明。中国政府采购网（`www.ccgp.gov.cn`）与采购人指定平台查公告；平台受限时说明，不用第三方转载代替最新正式文件。
2. **三类要求分开**：资格性要求（不满足即无效）／实质性响应要求／评分项，逐条摘录并留页码或章节号。“必须满足”与“争取得分”不混在一张清单。
3. **响应矩阵**：要求 → 应答 → 证明文件 → 标书位置 → 缺口 → 负责人。真实材料不足就写待补及对资格或分值的影响。
4. **材料核验**：有效期、使用授权、主体与人员对应关系、证书真伪线索。涉客户秘密、案件内容、个人信息的业绩材料按获准范围脱敏；不得复制签章或伪造证明。**编造业绩属于硬性禁止项**，发现缺口只写缺口。
5. **方案设计**：需求与法律问题 → 服务范围 → 项目组织与人员分工 → 工作步骤与里程碑 → 交付物 → 响应机制与时限 → 保密与利益冲突管理 → 质量控制 → 应急与退出。承诺须可实现、由有权人员确认；不承诺裁判结果，不暗示与办案机关的特殊关系。
6. **报价**：按采购文件核对税费、币种、计价单位、人员或工时、分项合计、总价、大小写、限价、报价有效期。缺价格授权或税务口径时给带条件的测算，不代定商业报价。商务偏离与技术偏离如实披露。
7. **程序性细节**：电子投标的 CA 证书与电子签章、文件格式与容量、命名规则、上传时点；纸质投标的密封、份数、正副本、签章位置；保证金形式与退还条件；联合体协议与分包限制；暗标或匿名评审的可识别信息处理（按规则办，不自作主张全篇脱敏）。
8. **复核**：引用、页码、交叉引用、附件完整性；实际生成 Word／PDF 时检查最终呈现；只交 Markdown 时标明尚需排版与签章，不称“可直接上传的电子标书”。
9. **无效投标风险清单**：固定清单逐项勾，不靠临场记忆。

| 类别 | 触发点 | 核对动作 |
|---|---|---|
| 资格 | 执业许可、社保、财务、信用记录、业绩原件缺失或过期 | 对采购文件资格条款逐条对证，记有效期 |
| 格式 | 密封、份数、正副本、签章位置、封面项目名与包号错 | 按“递交前检查表”逐项签字 |
| 时间 | 递交时点、电子上传完成时点 | 预留缓冲，记录实际上传完成时间 |
| 保证金 | 形式、账户、到账时点、退还条件 | 查银行到账凭据，不认“已汇出” |
| 报价 | 超限价、漏项、大小写不一致、与开标一览表不一致 | 工具比对＋人工复核分项合计 |
| 电子 | CA 证书有效期、电子签章、格式与容量、命名规则 | 提前一天试传 |
| 暗标 | 正文称谓、页眉页脚、文档属性、文件名、印章图 | 见第 11 项 |

10. **落标与救济（只给节点，不判胜算）**：政府采购质疑自知道或应知权益受损之日起 7 个工作日内提出，采购人 7 个工作日内答复；对答复不满或逾期未答复，15 个工作日内向财政部门投诉；超期不予受理。企业采购按其采购规则与合同争议条款办。具体主张成立与否属争议解决，转 [02 民商诉讼](02-civil-litigation.md) 或另聘，本模块不出实体结论。
11. **暗标脱敏**：按采购文件规则处理，不自作主张全篇脱敏。必查：自称「我所／本所」、页眉页脚、文档属性（`creator`／`lastModifiedBy`／`company`）、文件名、图片与印章元数据。工具：`tools/tender_consistency.py --anonymous`。
12. **业绩库与声明**：`data/credits.example.json` 记项目名、客户、年份、金额、角色、**可披露范围、授权状态**；投标时按采购要求匹配，输出「可用／需授权／不可用」。缺口由匹配算出，不由人临时回忆——这也从根上堵住了「差一项要不要编」。

## 工具

- `tools/tender_matrix.py 采购文件 --body 标书 --out matrix.csv`：抽候选要求行、按资格／实质性／评分分类、产出矩阵骨架、按 6 字片段重合率标「已应答／弱匹配／未找到」。分类靠关键词，必有误判，以原文与评标办法为准；它只保证不漏条。
- `tools/tender_consistency.py 标书目录 [--anonymous]`：查大写与小写金额矛盾、同一价格标签多值（含跨文件）、同一日期标签多值、文档属性泄露身份。
- `tools/tender_score.py 自评.json`：按最低价／基准价／固定价三种算法算价格分，输出总分、需争取项与降价边际（样例 `templates/tender-score.sample.json`）。
- `tools/tender_credits.py --credits data/credits.json --need 3 --years 2022-2025 --keyword 建设工程`：业绩按年份／关键词／金额匹配，分「可用／需授权／不符合」，缺口照实输出。

## 标准交付

- 项目摘要、投标可行性、硬性缺口、截止事项；
- 资格性与实质性要求检查表；
- 评分响应矩阵：

| 采购要求与定位 | 类型／分值 | 具体响应 | 证明材料与版本 | 章节／页码 | 满足情况与缺口 | 责任人 |
|---|---|---|---|---|---|---|
| | | | | | | |

- 标书内容或指定章节稿，按采购文件顺序组织；
- 报价核对表、商务／技术偏离表、证明材料与签章清单；
- 无效投标风险检查表（逐项勾选，含责任人与核对时点）、要求覆盖率报告（未覆盖条目单列）；
- 递交前检查表，分“已核对／待补／待负责人决定”。

## 自检

每个实质性要求都有对应；跨文件金额与日期一致；文档属性已清；评分写实且有证明；报价全稿一致；主体、人员、期限无错配；更正已合并；未造章造证、未披露未授权客户资料；资格硬缺口不靠“完全响应”掩盖；未取得负责人授权不发送、不承诺报价。
