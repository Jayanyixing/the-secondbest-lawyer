# 交付前总闸（一份清单，不再分散重复）

正式交付前逐行过一遍；命中任一条“不合格”就先修，再交付。模块内只保留该模块特有检查，通用项都在这里。

## 一、引用（最高优先级）

- [ ] 正文每个法条、案例、机关信息都能指回底稿编号；
- [ ] 每条底稿都有：四要素、来源渠道、具体链接或文件名、定位（页码／段落／小节）、读取范围、复核状态、登记日期；
- [ ] 支撑结论的条目都有 **8–60 字逐字摘录**，不是概述、不是套话（“本院认为”这类不算）；
- [ ] 摘录在正文引用处原样出现，没被改写或拼接；
- [ ] 进了结论的条目已**回读**，底稿记录回读日期；回读不一致的已降级为待取正文；
- [ ] 回读与官方复核分开记：商业库与转载件的正文可以「已回读」，官方复核只能「未核」；
- [ ] 首页写明「官方复核未核 N 条」；正式诉讼材料的未核条目已单列「提交前须核」清单，四列齐全（编号／待核事项／建议核对入口／核对备注），入口按条目类型预置；
- [ ] 没有出现 `标题`／`摘要` 级条目支撑裁判理由或结论；
- [ ] 没有“某法院认为”“司法实践普遍认为”“相关规定”这类无号引用；
- [ ] 案号、入库编号、指导案例编号、文号、条号没有一个是推出来的；
- [ ] 来自本地法条库的引用带「导入日期＋哈希」，并确认导入版本覆盖行为时点；
- [ ] 引用标准时写明「标准号＋年份＋名称＋条款号＋状态（现行／即将实施／废止／被代替）＋查询日」；
- [ ] 标准状态用的是官方口径（现行／即将实施／废止）；若用商业库的“部分失效／已被修改”，已注明来源；
- [ ] 一审未生效判决没有被写成生效裁判，对己方不利的后续改判没有被隐去；
- [ ] “待取正文”只出现在线索表，没混进结论段；
- [ ] 「无效／不发生效力／可撤销／可调减」这类结论都挂了 N-／C- 编号，没有依据的写成「法律判断待核（未登记依据）」，没写成确定结论。

## 二、时点与期限

- [ ] 行为时点、规范公布／施行／修订、程序节点分别核过；
- [ ] 实体与程序、民事与刑事分别判断，没有一句“以最新规定为准”；
- [ ] 每个日期带 `已核`／`〔假设：…〕`／`待核` 标签之一；
- [ ] 期限有计算过程，节假日按当年官方安排核过，时区写明。

## 三、事实

- [ ] 事实标注四态（材料记载／当事人陈述／分析推断／待查）；
- [ ] 页码与卷页引用落在材料索引区间内；
- [ ] OCR 误识别的关键字段已核原图；
- [ ] 不利事实已呈现，没有只挑有利的写；
- [ ] 缺项用 `【待补：…】`，没有一个数字是估出来的。

## 四、动作与授权

- [ ] 没有把未执行的事写成已提交／已发送／已办成；
- [ ] 检索受限、工具未接入、权限不足写在结论旁；
- [ ] 未承诺未接入的提醒、监控或后续跟进；
- [ ] 对外发送、签署、报价前已确认授权。

## 五、合规

- [ ] 首次确认三项已做（同一案件会话内一次）且记入交接卡（AI 处理授权／数据留存与存放地／脱敏或原件上传确认）；未确认前没有处理案件材料；
- [ ] 措辞没有宣称「已合规」「符合监管要求」，只写「已按你确认的范围处理」；
- [ ] 脱敏按口径执行（证件号只留后 4、银行账号后 4、手机号后 4、姓名留姓、地址到区）；
- [ ] 未上传整卷、完整流水、商业秘密到公共检索；
- [ ] 利益冲突线索已单列并交承办律师；
- [ ] 没有伪造证据、签章、业绩、笔录，没有串供、毁证、隐匿财产、非法查个人信息的内容。

## 六、交付形态

- [ ] 开头三行齐全：结论／最紧迫／最大缺口；
- [ ] 篇幅符合上限（咨询 ≤15 行；简报 ≤1 页）；
- [ ] 模式标注正确（`〔自查〕`／`有限复核`／`独立复核`）；
- [ ] 免责与保留只写一次，放在末尾；
- [ ] 已跑 `tools/citation_lint.py` 并把结果附在附录；
- [ ] 交付 docx/xlsx 时：已打开检查排版，【待补】占位符全部替换，份数与签名位正确；
