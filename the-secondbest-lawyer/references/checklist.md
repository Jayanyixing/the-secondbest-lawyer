# 交付前总闸（一份清单，不再分散重复）

正式交付前逐行过一遍；命中任一条“不合格”就先修，再交付。模块内只保留该模块特有检查，通用项都在这里。

## 一、引用（最高优先级）

- [ ] 正文每个法条、案例、机关信息都能指回底稿编号；
- [ ] 每条底稿都有：四要素、来源渠道、具体链接或文件名、定位（页码／段落／小节）、读取范围、复核状态、登记日期；
- [ ] 支撑结论的条目都有 **8–60 字逐字摘录**，不是概述、不是套话（“本院认为”这类不算）；
- [ ] 摘录在正文引用处原样出现，没被改写或拼接；
- [ ] 进了结论的条目已**回读**，底稿记录回读日期；回读不一致的已降级为待取正文；
- [ ] 没有出现 `标题`／`摘要` 级条目支撑裁判理由或结论；
- [ ] 没有“某法院认为”“司法实践普遍认为”“相关规定”这类无号引用；
- [ ] 案号、入库编号、指导案例编号、文号、条号没有一个是推出来的；
- [ ] 一审未生效判决没有被写成生效裁判，对己方不利的后续改判没有被隐去；
- [ ] “待取正文”只出现在线索表，没混进结论段。

## 二、时点与期限

- [ ] 行为时点、规范公布／施行／修订、程序节点分别核过；
- [ ] 实体与程序、民事与刑事分别判断，没有一句“以最新规定为准”；
- [ ] 每个日期带 `已核`／`〔假设：…〕`／`待核` 标签之一；
- [ ] 期限有计算过程，节假日按当年官方安排核过，时区写明。

## 三、事实

- [ ] 事实标注四态（材料记载／当事人陈述／分析推断／待查）；
- [ ] 页码与卷页引用落在材料索引区间内；
- [ ] OCR 误识别的关键字段已核原图；
- [ ] 不利事实已呈现，没有只挑有利的写；
- [ ] 缺项用 `【待补：…】`，没有一个数字是估出来的。

## 四、动作与授权

- [ ] 没有把未执行的事写成已提交／已发送／已办成；
- [ ] 检索受限、工具未接入、权限不足写在结论旁；
- [ ] 未承诺未接入的提醒、监控或后续跟进；
- [ ] 对外发送、签署、报价前已确认授权。

## 五、合规

- [ ] 脱敏按口径执行（证件号前 6 后 4、账号后 4、姓名留姓、地址到区、手机前 3 后 4）；
- [ ] 未上传整卷、完整流水、商业秘密到公共检索；
- [ ] 利益冲突线索已单列并交承办律师；
- [ ] 没有伪造证据、签章、业绩、笔录，没有串供、毁证、隐匿财产、非法查个人信息的内容。

## 六、交付形态

- [ ] 开头三行齐全：结论／最紧迫／最大缺口；
- [ ] 篇幅符合上限（咨询 ≤15 行；简报 ≤1 页）；
- [ ] 模式标注正确（`〔自查〕`／`有限复核`／`独立复核`）；
- [ ] 免责与保留只写一次，放在末尾；
- [ ] 已跑 `tools/citation_lint.py` 并把结果附在附录。
