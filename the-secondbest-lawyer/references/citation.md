# 引用与可追溯（本技能最高优先级规则）

> 本文件优先于其他模块的行文习惯。凡进入交付物的法条、案例、机关与主体信息，**必须先有底稿条目，再以固定格式引用**。没有底稿条目的一律不准进正文。

## 四条铁律

1. **无底稿，不进正文。** 先登记，后引用；顺序不可颠倒。
2. **四要素齐全。** 案例：完整案号 + 法院全称 + 裁判日期 + 审级（＋二审／再审情况）。规范：全称 + 条款 + 制定机关 + 施行日期（＋最新修订）。
3. **一依据一出处一定位。** 每条依据都要能落到具体页码、段落、小节或时间点；落不到就降级为“待取正文线索”，不得用来支撑结论。
4. **未读到全文，不得复述裁判理由。** 摘要、要旨、标题只能用来定位，不能当作法院已经那样说。

做不到第 2、3 条时，标准动作是**写清缺什么、怎么补**，而不是把缺口填成内容。

## 引用底稿

交付物附一份底稿，正文每个引用都指回这里。编号固定前缀：`N-` 规范、`C-` 案例、`M-` 机关／联络／主体信息。

| 字段 | 要求 |
|---|---|
| 编号 | N-01 / C-01 / M-01，正文以 `[C-01]` 标注 |
| 类型 | 法律／行政法规／司法解释／地方性法规／规章／规范性文件／法院文件；指导性案例／入库参考案例／典型案例／普通裁判／仲裁裁决 |
| 名称与四要素 | 规范全称、条款；案例案名、完整案号、法院、裁判日期、审级 |
| 来源渠道 | 见下方封闭词表 |
| 出处 | 具体原文链接（非首页、非搜索页）；或导出文件名 + 页码／小节标题；或“用户口述” |
| 定位 | 页码、段落、小节标题或音视频时间点；页码范围要写“第 X–Y 页” |
| 读取范围 | 见下方封闭词表 |
| 官方复核 | 见下方封闭词表 |
| 生效与后续 | 见下方封闭词表 |
| 登记日期 | 本次实际读取的日期，不与页面发布日期混同 |

一页底稿表即可，不必另立长文档。条目多时按类型分表，编号连续。

## 封闭词表（只准用这几个词，不自造近义词）

**读取范围**：`全文` ／ `节选（第X–Y页｜第X小节）` ／ `摘要` ／ `标题` ／ `未读`

**来源渠道**：`官方页面` ／ `商业库` ／ `用户提供导出件` ／ `用户口述` ／ `未取得`

**官方复核**：`已核（与官方原文一致）` ／ `未核（仅商业库或转载）` ／ `不适用（用户材料，不涉官方）`

**生效与后续**：`已确认生效` ／ `未确认` ／ `存在后续程序（列明审级与结果）`

**引用状态（写在正文或表内）**：`可直接引用` ／ `仅作背景` ／ `待取正文`

词表之外的混用（如“已核对原文”“已读官方裁判全文”“待核线索”“检索受限”）视为状态不明，等同于未核验。

## 正文引用格式

规范：
> 《中华人民共和国民法典》第 X 条第 X 款〔N-03｜官方页面｜已核〕

案例：
> （20XX）京 XX 民终 XX 号，北京市第 X 中级人民法院，20XX-XX-XX，二审〔C-04｜商业库｜全文｜官方复核：未核｜生效：未确认〕

首次出现写全，后文用短号 `[C-04]`。同一段落连续引用多个依据时，每个依据单独给号，不合并成一个链接。

## 禁止模式（出现一条即不合格）

- 只给标题、公众号文章、律所推文、百科、问答或搜索结果页链接；
- 一个链接同时支撑两个以上不同案例；
- 把转载、汇编、二次解读当作独立案例；
- “某法院认为……”“司法实践普遍认为……”“有判例支持……”而无案号；
- 用“根据相关规定”“依照有关法律”替代具体条款；
- 只读摘要或要旨，却写出裁判理由、合议庭观点或判决主文；
- 编造或“合理推测”案号、入库编号、指导案例编号、文号、条号；
- 把未生效一审判决说成生效裁判，或隐去对己方不利的后续改判；
- 用自己检索到的总量、命中数反推“此类案件胜诉率”。

## 降级路径（读不到正文时）

输出一张 `待取正文` 表：案号或标题｜来源平台｜已知信息｜需要补的正文段落｜取用方式（用户自己导出／授权商业库／申请查阅）。附两至三组可直接粘贴的检索式与筛选条件。这张表可以进交付物，但**不得进结论段**，也不得在摘要里写“已核”。

## 交付前机械校验

正式文书、法律意见、尽调、标书交付前运行 `tools/citation_lint.py`（见仓库根目录 README）。校验器检查：正文案号是否都在底稿；底稿是否缺定位／读取范围／复核状态；摘要级条目是否被用来支撑理由；日期类断言是否缺假设标签；是否出现绝对化措辞。校验不通过不得标注为可交付。
