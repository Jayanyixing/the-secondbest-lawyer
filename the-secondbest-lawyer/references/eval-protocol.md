# 回溯评测方法（把“我觉得好用”换成分数）

本技能没有真实案件准确率评测。这份文件是**怎么做那个评测**的操作规程：用已结案件回溯，盲评打分。跑完 10 例，才有资格说“可用”。

## 一、选案

- **10 件已结案件**，覆盖至少 5 个模块（建议 02×3、03×2、05×2、06×1、07×1、08×1）。
- 材料齐全：文书、证据、往来、结果都有。
- 结论已定：判决书／裁决书／结案报告在手，作为“标准答案”封存。
- **脱敏**：当事人姓名、身份证、账号、地址按主 `SKILL.md` 口径处理；涉未成年人、性侵等不公开案件不进评测。

## 二、盲法

1. 把“标准答案”（判决理由、代理词结论、结案报告）**移出**给模型的工作目录。
2. 只给：材料 + 一句任务指令（例如“站在原告立场出策略简报与证据矩阵”）。
3. 同一案件只跑一次，不追加提示、不手工纠偏——真实的第一次输出才是被评的对象。
4. 记录：耗时、工具失败次数、是否用到联网、是否触发降级。

## 三、评分（6 维 × 0–3 分）

| 维度 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| D1 事实准确 | 编造事实或页码 | 多处偏差 | 少量小错 | 与材料一致 |
| D2 引用可追溯 | 有编造案号／法条 | 多半不可追溯 | 大体可追溯，缺摘录 | 全部带摘录且回读 |
| D3 时点适用 | 套最新法 | 未区分时点 | 大体正确 | 实体程序分别核，有理由 |
| D4 不利面覆盖 | 只写有利 | 提一句 | 有专门段落 | 对方最强攻击与化解都写了 |
| D5 交付可用 | 不能看 | 需大改 | 小改可用 | 可直接交给承办律师 |
| D6 边界诚实 | 装懂或越界 | 含糊 | 提示了缺口 | 明确划界并给补法 |

**阻断项**（任一出现，该案直接记 0，不参与均分）：

- 编造案号、条号、入库编号、指导案例编号；
- 摘录与原文不符或根本没读却写摘录；
- 把未生效裁判写成生效；
- 编造进度、业绩、签章。

## 四、门槛

| 平均分 | 结论 |
|---|---|
| ≥ 2.6 且无阻断 | 可推荐给同事使用 |
| 2.2–2.6 | 可用，但需律师逐份复核 |
| 1.8–2.2 | 仅作初稿，需大改 |
| < 1.8 | 不可用，回炉 |

另看两项硬指标：**阻断率**（有阻断的案件数 / 10）应为 0；**回读率**（D2 中标注已回读的条目 / 全部引用条目）应 ≥ 90%。

## 五、怎么跑

```bash
# 1. 复制模板
cp eval/case-card.template.json eval/cases/C01.json
cp eval/scoring.template.csv eval/scores.csv

# 2. 每案跑完后填一行分数（0-3），blocker 填 1 表示出现阻断项

# 3. 汇总
python3 tools/eval_score.py eval/scores.csv
```

脚本会输出各维度均分、阻断率、结论档位，并在不达标时返回非零退出码。

## 六、跑完要交付什么

1. 分数表（脱敏）；
2. **失败模式清单**：哪一维最弱、典型错法是什么（例如“类案只读摘要”“期限不给日期”）；
3. 针对失败模式的修订建议，按影响排序；
4. 一句结论：能不能给同事用。

不要把评测分数当宣传话术。分数低就改，不要改评分标准。
